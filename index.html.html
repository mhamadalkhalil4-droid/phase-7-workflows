1Bounce Category Routing

ℹ️ Every time Phase 6 marks a collection as Bounced it immediately triggers this workflow. The system reads the bounce reason code and routes the collection to the correct recovery workflow. The routing is deterministic — the same reason code always maps to the same category.

2NEW DD CASES — New Mandate Recovery
Codes: A · E · F · G · N · O · V · W · X · Y · Z  ·  The payer's account or card is unusable — a new mandate is required
ℹ️ System creates the new mandate first, then cancels the old one, then sends the payer a reason-specific message with the new mandate creation link. This order is intentional — a valid mandate must exist before the old one is removed.
ℹ️ The original bounced collection stays Bounced and is retried once the new mandate is approved by the bank.

3NO ACTION — Payer Deceased
Code: D (Payer Deceased)  ·  No automated action · No payer contact · Ops review only
ℹ️ The account holder is deceased. There is no payer to contact and no account to retry. The system flags the collection and makes it visible to the ops team. No message is sent. No retry is attempted. The only available action is for ops to close the case manually.

7SILENT RESUBMISSION — Auto-Compare DDR/DDA & Retry
Code: R (DDR Details Inconsistent with DDA Details)  ·  System auto-corrects mismatch and resubmits · Ops intervenes after half of Max Bank Submissions
ℹ️ The DDR (Direct Debit Request) details do not match the DDA (Direct Debit Authority / mandate) details stored in the system. The system automatically compares the two, corrects the mismatch, and resubmits silently. No payer contact is made.
⚠️ Once Bank Submissions exceeds half of the configured Max Bank Submissions, the automated loop pauses and the ops team must review and intervene manually before any further resubmission.

8SCHEDULED RETRY — Wait for Next Calendar Period
Code: U (Amount Not Yet Due)  ·  System waits for the next calendar period based on mandate frequency then auto-submits
ℹ️ The bank returned the collection because the amount is not yet due. The system waits until the start of the next calendar period based on the mandate's frequency (e.g. Monthly mandate → waits until the 1st of next month; Weekly → next Monday) and then resubmits automatically. No message is sent to the payer.
ℹ️ If the bank bounces again with a different reason code, WF 1 re-routes to the appropriate group for that new code.
